# Post-experiment supervised corrections for maths stages

An authorized pending policy is applied by the pipeline before starting its next worker, after the generated-correction experiment finishes. The selected checkpoint is backed up; weights, optimizer and cursor are preserved. SIGReg becomes 0.0003 and the training-loss threshold remains 0.003. The one-time 50-round validation pause is cleared. Correction mining is enabled only if the experiment selects the targeted arm; otherwise ordinary training resumes with the requested SIGReg and loss threshold.

Every maths stage first uses its ordinary stage/replay mixture until round-average cross-entropy (excluding SIGReg) reaches 0.003. The threshold is latched for that stage. Mining cannot start during this acquisition period. Once unlocked, the normal validation and recovery system continues. Every 20 normal stage rounds, at most 256 training-only questions are selected for generation; at most five subsequent rounds emphasize verified failures. At stage transitions, the controller starts fresh, so a new stage must reach the threshold again.

Mining excludes every validation, test and quarantined family. Its evidence files are named `<phase>_generated_errors_<round>.json`. Saved controller state includes mining round, training IDs and correction rounds remaining, enabling safe partial-round resume. A loaded correction pool is checked against training IDs. Training uses 60% current-stage failure examples when available, 20% other current-stage practice and 20% prior-stage replay; prior-stage failures receive attention within the replay allocation. With no current failures, that allocation returns to normal current-stage practice.

All maths stages support generated answer/format checks against regenerated solver targets. Detailed first-invalid-step analysis remains limited to the arithmetic verifier's supported syntax. Unrecognized correct-answer traces are not declared mathematically wrong and are excluded from correction mining. This is not a complete proof checker for advanced mathematics. Existing canonical trace acceptance gates remain unchanged.

The dashboard status exposes mining progress, failure count, supervised_correction and correction_rounds_remaining. The running experiment retains its original settings; the pending policy takes effect only during the automatic post-experiment handoff.
