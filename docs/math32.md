# V3.2 standalone mathematical curriculum

V3.1 is paused and preserved. V3.2 starts fresh weights; no coordinator, bridges, Qwen or other specialist runs. The architecture is six causal layers, width 384, six heads, SwiGLU FF width 1536, RMSNorm and zero dropout. Inputs use stable semantic operation/field tokens and reversed digit sequences. Embeddings combine tokens, operand/result roles, sinusoidal sequence positions and digit positions that reset within each numeric span. Random shared digit-position offsets 1–64 are used during training and zero at inference. Target roles and positions are derived causally; answer length or carry labels are not supplied to inference.

The vocabulary has 512 fixed slots, with inactive reserved IDs masked out of prediction. The complete vocabulary and its checksum live alongside the dataset. Existing token IDs must never be renumbered. This architecture is larger than V3.1; it is not a parameter-matched ablation.

The curriculum is split into 70 narrower stages. Early stages separate direct single-digit addition/subtraction, decomposition, exchanging a ten, deciding whether borrowing is necessary, no-carry addition, crossing ten and explicit column subtraction. Column subtraction returns [units,tens,result]; regrouping returns [remaining_tens,ones_after_exchange]. These are separate named operations, not hidden detail flags. Ordinary arithmetic returns only the result. Counting, missing values, signed arithmetic and fraction representation are retained. Later operations are separated and ordered so differentiation precedes integration, combinations precede probability, and GCD precedes Bezout/modular inverse. These later stages remain bounded synthetic exercises, not comprehensive degree-level mathematics.

New foundations are exhaustively generated from stated bounded domains. Later examples are repartitioned from V3.1 training data only; V3.1 evaluation questions are not reused as V3.2 training. Family-level assignments prevent train/validation/test overlap, including reversed addition pairs. Counts are not artificially inflated: the first stage has 43 unique training questions, six validation questions and six sealed test questions. Its small held-out set is a finite-domain check, not evidence of broad numerical generalization.

Each 4,096-example training round draws 75% active-stage examples and 25% prior-stage replay, balanced by stage and computational case. Cases include carries/chain length, borrowing decisions, comparison outcomes, digit lengths, and numerical magnitude/sign for other operations. Loss is masked on the question and applied to result tokens plus EOS. AdamW uses peak LR 0.0003 with 300 update warmup; SIGReg coefficient is 0.0003 with 64 projections.

Automatic evaluation stays off until round-average prediction loss reaches 0.003. It then runs at 20-round boundaries, immediately after a full pass to confirm it, and at recovery boundaries. There is no evaluation after individual optimizer steps. Promotion requires two consecutive full active validation passes plus a fixed cumulative-retention panel, all at 100%, and at least three post-threshold normal rounds. A once-only sealed stage test then guards promotion. If sealed testing fails, training pauses instead of learning from the test. Failed normal blocks of 240 rounds trigger up to 30 rounds focused on failed training cases, followed by normal consolidation; four unsuccessful repair cycles pause for inspection.

Checkpoints preserve weights, optimizer, RNG, dataset/config binding and partial-round cursor. A STOP file requests a safe save. Manual validation remains available from the dashboard and cannot promote by itself. Accepted stages retain their own checkpoint. Start with `scripts/start_math32.ps1`; the dashboard is served by the existing local dashboard backend pointed at G:/ctfn-text/artifacts/v3_2 on port 8792.

Dataset build: `python -m math32.data`, then `python -m math32.prepare`. The preparation audit checks every target, every tokenizer round trip and the full sequence length against context 256. Tests cover digit order, loss masking, role causality, causal transformer output, actual CUDA gradients, regrouping, family symmetry and sampling balance. A short live training check is required after launch.
