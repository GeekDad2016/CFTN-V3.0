# Stage 2 subskill recovery experiment

The remaining errors include correct arithmetic followed by an incorrect equality decision, borrowing without decrementing the tens digit, and repeated-digit generation. Criterion-level recovery could exit after two small routine panels passed. The opt-in subskill path now requires two complete focused panels, checked every five recovery rounds and immediately after a first pass. It returns to normal-stage consolidation before the usual two consecutive full promotion checks. Other stages and legacy controllers retain their behavior.

`subskill_data` builds a training-only derivative from balanced_validation_v4. It adds 5,249 expression comparisons, stratified by decision, operation pair, shared units, different number lengths, adjacent values, and results containing eleven. All added examples exclude held-out comparison families, including quarantine, side swaps and commutative addition. Validation and test files remain byte-identical. There are 45 existing Stage 2 borrowing examples; these receive focused sampling rather than duplicate records. Recovery uses 60% focused examples, 20% normal-stage examples and 20% prior-stage replay.

`python -m cftn_v3.subskill_probe` runs an exclusive GPU experiment from the protected round 682 boundary checkpoint. It evaluates the start, then runs five rounds of 4,096 examples per arm with the same initial weights, optimizer and RNG. The baseline uses the original normal sampler and dataset. The candidate uses the new dataset and a predetermined comparison/borrowing/repeated-digit focus schedule. Learning rate, model size and SIGReg remain unchanged. Equal example budgets are used; sequence lengths can produce different token and optimizer-step counts.

Each endpoint receives the same full 1,018 active and 273 retention questions. Candidate adoption requires fewer active errors than baseline and no increase in any answer, trace or format error count on either panel against both baseline and start. A tie keeps baseline if it does not regress against start; otherwise the start is restored. This short test provides initial evidence, not a claim of stable mastery. It jointly tests added coverage and focused sampling rather than isolating either contribution.

After selection, the process automatically releases the GPU lock and resumes the curriculum. A selected candidate enables subskill recovery for remaining failures, with ordinary consolidation and strict 100% first-five-stage gates. The protected checkpoint, full reports, sample IDs, decision and logs remain under `G:/ctfn-text/artifacts/v3_1/subskill_probe`. The dashboard follows the current experiment arm through queue.json. An experiment exception records error.json and restores the original checkpoint/config; it does not silently adopt an incomplete result.

Validation: 20 controller, subskill, selection and foundation-gate tests passed; generated-example held-out exclusions were independently checked. Live CUDA trial results are pending.
